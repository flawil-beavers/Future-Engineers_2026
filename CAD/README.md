# CAD Folder

This folder contains the Fusion 360 model, the scripts used to characterize the Ackermann steering geometry, and the generated outputs that feed into the robot firmware.

## Files

| File | Description |
|------|-------------|
| `Car_v71.3mf` | The 3D model of the car (version 71) used in Fusion 360. |
| `Car_v72.f3z` | The editable Fusion 360 archive of the car (version 72) — open this in Fusion for editing/scripting. |
| `AckermannExporter.py` | Fusion 360 Python script that sweeps the servo joint and records the resulting wheel angles and pin-slot slide distance. |
| `analyze_ackermann.py` | Standalone Python script that loads the exported data, fits curves, plots the results, and generates a C++ header for the firmware. |
| `ackermann_data.csv` | Raw sweep data produced by `AckermannExporter.py`. |
| `ackermann_analysis.png` | Plot generated by `analyze_ackermann.py` showing the fitted curves and slide distance. |
| `ackermann_lut.h` | C++ header generated by `analyze_ackermann.py` containing polynomial coefficients and a lookup table (LUT) for the firmware. |
| `parking_exit_swept_search.py` | Standalone, standard-library Python search for a collision-free multi-point exit from the proportional parking gap. |
| `parking_entry_swept_search.py` | Searches outward from the centred 165 mm scoring pose, reverses the controls for entry, and checks the entry across 16 gap/pose/heading tolerance cases. |
| `PARKING_EXIT_PATH_SIMULATION.md` | Geometry, Ackermann motion, collision checking, search method, selected route, limitations, and physical-validation procedure for the parking exit. |
| `PARKING_ENTRY_DESIGN.md` | Rules-backed geometry, rejected reverse-exit baseline, sensor-localization concept, safety gates, and ordered work for final parallel parking. |

Driving simulations use these Ackermann results but are maintained separately
in [`simulation/`](../simulation/README.md). That folder contains motion and
collision models, generated paths, log fixtures, physical reference images,
and their validation documentation.

The final-parking design basis is documented in
[`PARKING_ENTRY_DESIGN.md`](PARKING_ENTRY_DESIGN.md). It intentionally does not
define firmware segment distances until a fully contained target passes the
same swept-envelope and tolerance process.

## AckermannExporter.py

`AckermannExporter.py` is a **Fusion 360 script** (run from the *Scripts and Add-Ins* dialog) that characterizes the Ackermann steering geometry of the model.

### Adding the script to Fusion 360

1. In Fusion 360, open **Tools → Scripts and Add-Ins…** (older versions use **Utilities → Scripts and Add-Ins**).
2. In the dialog, select the **Scripts** tab.
3. Click the **+ (Create)** button at the bottom-left.
4. Enter a name (e.g. `AckermannExporter`) and choose where to store it. Fusion creates a new script folder (for example under `%APPDATA%\Autodesk\Autodesk Fusion 360\API\Scripts\AckermannExporter`).
5. In the newly created folder, replace the generated `AckermannExporter.py` (and delete the default sample script that Fusion adds) with the contents of this repo's `CAD/AckermannExporter.py`.
6. Back in the *Scripts and Add-Ins* dialog, select `AckermannExporter` in the list and click **Run**. The script will prompt for the sweep angle and export the data.

### What it does

1. Prompts the user for a **maximum servo sweep angle** (e.g. `30`).
2. Locates the joints named `ServoJoint`, `WheelJointL`, and `WheelJointR` in the model.
3. Sweeps the servo joint from `-max_deg` to `+max_deg` in 1° steps.
4. At each step it records:
   - The servo angle (°)
   - The pin-slot **slide distance** (mm)
   - The **left** and **right** wheel angles (°)
5. Writes all samples to `C:/Users/Public/ackermann_data.csv`.

### Requirements

- The Fusion model must contain joints named exactly:
  - `ServoJoint`
  - `WheelJointL`
  - `WheelJointR`
- The script must be run from within Fusion 360 (it uses the `adsk` Fusion API).

## analyze_ackermann.py

`analyze_ackermann.py` is a **standalone Python script** that processes the data exported by `AckermannExporter.py`.

### What it does

1. Loads `ackermann_data.csv` (from `C:/Users/Public/` or the current directory).
2. Normalizes the wheel angles from `[0, 360]` into the standard `[-180, +180]` range.
3. Fits a **3rd-order polynomial** to the left and right wheel angle data:
   `Angle_Wheel = a·x³ + b·x² + c·x + d`
4. Plots the data and fitted curves:
   - Servo angle vs. wheel angles (with fits)
   - Servo angle vs. pin-slot slide distance
5. Saves the figure as `ackermann_analysis.png` in the same folder as the script.
6. Generates `ackermann_lut.h` — a C++ header for the PlatformIO firmware containing:
   - The fitted polynomial coefficients
   - A high-performance **lookup table (LUT)** with linear interpolation
   - Helper functions `getLeftWheelAngle()`, `getRightWheelAngle()`, `getLeftWheelAngleLUT()`, and `getRightWheelAngleLUT()`

### Requirements

- Python 3 with `pandas`, `numpy`, and `matplotlib` installed:
  ```bash
  pip install pandas numpy matplotlib
  ```

## Workflow

1. Open `Car_v71.3mf` in Fusion 360.
2. Run `AckermannExporter.py` from the *Scripts and Add-Ins* dialog and enter the desired sweep angle.
3. Run `analyze_ackermann.py` to generate the plot and the C++ header:
   ```bash
   python analyze_ackermann.py
   ```
4. In the current case, the firmware does **not** yet use `ackermann_lut.h`. The robot drives the steering servo directly by command angle and uses its own turn-radius calibration (see `calibration.cpp`, which fits the Ackermann `K` factor). Use the generated `ackermann_analysis.png` to verify the steering geometry, and treat `ackermann_lut.h` as a reference for the wheel-angle vs. servo-angle relationship. If you later want the firmware to consume this header, copy `ackermann_lut.h` into `include/` and call `Ackermann::getLeftWheelAngle()` / `Ackermann::getRightWheelAngle()` (or the LUT variants) — but that integration is not currently part of the firmware.
